# Refactor data-model — DataInstance

> **Status:** ✅ done — complete (commits `ae6c4715 refactor data-instance`, `2d1862e6 improve jsonld use`).
>
> Extracted from **Phase 4** of [`refactor-data-model-followup.md`](refactor-data-model-followup.md). That plan's Phases 1–3 converted the CRUD domain resources to JSON-LD POJOs (raw JSON-LD GET/PUT, SPARQL patches via module functions). DataInstance was the remaining model with a **mixed PUT/PATCH/blob write side** and a **write-side class unused in production** — the scope decision has been resolved (**write side removed**, iteration reduced to bare IRIs), and the **read path is now N3-free (framed JSON-LD)**. This plan is complete.

## Current shape (after the write-side removal + N3-free read)

- **Iteration**: `Grant.getDataInstanceIterator(grant, factory)` — yields `AsyncIterable<string>` (instance IRIs / `id`s), not class instances. AllFromRegistry → `dataRegistration.contains`; SelectedFromRegistry → `grant.hasDataInstance`; Inherited → walks the parent's instances and resolves child IRIs via the module-level `getChildInstanceIris(parentGrant, parentIri, childShapeTree, factory)` — **framed read** (see below). The only production consumer, components `DataRegistry.listDataInstances`, iterates the ids (dedup via `seenInstances`), then re-reads via `factory.readable.dataInstance`.
- **Read**: `DataInstanceData` POJO (id, shapeTreeIri, label, isBlob, children, dataRegistration) built via `factory.readable.dataInstance`. **N3-free**: `frameDataInstance(iri, factory, shapeTree, docIri?)` fetches the JSON-LD doc and frames it with a per-shape-tree context (`dataInstanceContext`: `describesInstance` → `label`, `nfo:fileName` → `fileName`, each reference's `viaPredicate` IRI as its own key with `@type: @id` + `@container: @set`); `labelFromNode` (describesInstance value or nfo:fileName), `childIris` (child IRIs for a referenced tree), `computeChildren` (counts + shape-tree-description labels). Blob reads keep `discoverDescriptionResource` (Link header) + description-resource fetch (framed with the blob IRI as subject). `isBlob` unchanged.
- **Write**: removed — the `DataInstance` class is deleted, `Grant.newDataInstance` removed (`iriForNew` stays — used by `application.ts`), `base-factory.ts`'s class factory method removed, `ReadableDataRegistrationProxy.newDataInstance` removed. Blob upload/description-resource patching is now entirely the app's job (vuejectron already does it via rawFetch + LDO). The registration proxy itself (`ReadableDataRegistrationProxy` + `DataOwner.selectRegistrations`) was removed — it was test-only (vuejectron doesn't import data-model; interop-application doesn't use it).
- **Consumers**: components `DataRegistry.listDataInstances` (iteration → ids, then `readable.dataInstance` — read only), authorization-agent `findAgentsWithAccess`/`shareDataInstance` (readable).

## Steps / decisions — status

1. **Scope decision (write-side class) — ✅ resolved: removed.** No production caller of `newDataInstance`/`.update()`/`.delete()`; the iterator consumer used class instances solely for `.iri` then re-read the POJO; vuejectron re-implements blob create/update with rawFetch + LDO. Removed: the class, `Grant.newDataInstance`, `base-factory.dataInstance` class factory, proxy `newDataInstance`, write-side test suite + `newDataInstance` test blocks. Later the whole proxy + `selectRegistrations` was removed as test-only cleanup. `Grant.canCreate` kept (test-only, stays per recorded decision). Behavioral note: the old `findChildGrant` guard ("child instance can not have child instances") is not preserved — an Inherited grant whose parent is itself Inherited recurses up the grant chain instead of throwing (terminates — grants form a tree).
2. **Read path N3-free — ✅ done.** `fetchDataInstanceDataset` (parseJsonld → N3 Store), `computeLabel`, `computeChildren`, `label`, `buildChildrenInfo` replaced by the framed read (`frameDataInstance` + `labelFromNode` + `childIris` + `computeChildren` over the framed node). `getChildInstanceIris` (Inherited branch) uses the same framed read. The dead `label`/`buildChildrenInfo` helpers were deleted with the rewrite.
3. ~~Whatever remains (blob SPARQL patch, child-reference patches) stays on the quad infra~~ — **void**: the write side is gone; the quad machinery in `data-instance.ts`/`grant.ts` was fully replaced.
4. **Test consolidation — ✅ done.** Write-side `test/data-instance.test.ts` deleted (its only surviving logic, the child-instance iteration, is covered by `inherited-data-grant.test.ts`'s iterator counts). `readable/data-instance.test.ts` un-skipped with real read tests: POJO shape (id/shapeTreeIri/isBlob/children), missing-registration throw, and label/children from the framed read (count + child shape tree).

## Decisions (recorded)

- **`Grant.canCreate` stays** — kept even though it is test-only (application.ts implements its own); no removal.
- **Child-guard recursion is accepted** — the old `findChildGrant` throw ("child instance can not have child instances") is not restored; an Inherited grant whose parent is itself Inherited recurses up the grant chain (terminates — grants form a tree).
- **`ShapeTree.getPredicateForReferenced` deleted** — its only production caller (grant.ts's quad-walking `getChildInstanceIris`) was replaced by the framed read, and `childIris` now does the equivalent find-and-throw inline. The function and its test were removed; shape-tree's remaining quad-based read (`fromDataset`/`fromJsonLd`/`getDescription`) is the followup plan's own item.
